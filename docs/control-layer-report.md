# 播放控制层交付记录

需求基线：补齐统一命令接口、可观察状态、控制面板和可选展示协调器，保留已有核心 API 和简化接入入口。

## 实现

- `PlaybackController`：列表和单视频共享 play/pause/retry/replay/seek/speed/mute/toggle/close 命令。
- `PlaybackState`：不可变的媒体身份、播放状态、阻塞原因、能力、进度和安全错误码快照。引擎事件驱动通知，仅在可见播放且有订阅时定时更新进度。
- `PlaybackStateStore`：立即回放、去重、可取消订阅、重入事件顺序、终态通知与观察者释放。
- `PlayerControlView`：播放/暂停、结束重播、错误重试、静音、倍速、播放/缓冲进度及全屏按钮。支持触摸、键盘和无障碍跳转；脱离窗口自动退订。
- `FullScreenCoordinator`：复用当前视图和播放租约，在沉浸式窗口内展示，返回或生命周期停止时恢复父容器、索引和布局；提供相同协议的全屏面板。
- 两个示例通过一行 bindControls 接入统一控制面板和全屏协调器；进入全屏时冻结原容器选播，退出后恢复先前选播与手势设置。

暂停、隐藏和媒体切换会使待执行的手动请求失效。已授权手动播放在同一媒体的宿主重新就绪时继续有效；重试显式重新准备失败媒体并重新检查策略。控制面板和展示协调器不创建、释放或直接操作底层 Player。

## 验证

- 56 项单元测试通过，包括 7 项新增状态存储及能力用例。
- 核心、UI、示例编译及静态检查通过；新 UI 模块无静态检查发现。核心保留依赖版本建议，示例保留原 DataExtractionRules 警告。
- API 28 UI 模块 10 项设备用例通过（包括 3 项新增控件/展示测试）：命令路由、无障碍跳转、订阅解绑、全屏归还和停止退出，以及原有绑定回归。
- API 28 核心 5 项新用例通过：关闭终态、暂停取消授权、手动授权跨宿主就绪、同媒体错误重试、单视频协议一致性。原有异步授权与详情接管两项也通过。
- API 28 的两个旧预热用例未通过其双引擎运行前提：设备 heapgrowthlimit=48m，低于框架 192MB 策略阈值；未改变该策略或这些断言。
- API 35 已执行核心 10 项，8 项通过（含精确预热恢复、详情接管、预热截止）；异步授权首帧等待和列表相邻预热两项仍未通过，未判定为环境问题或本次改动已解决。

已有测试片原为 1080p High profile，API 28 解码器初始化失败，因此改用 360×640 Baseline 测试片，保留 72 帧、24fps 和三秒视频；只有第一帧为关键帧，原有两秒精确恢复断言仍需跨帧解码。此后，测试片及两个业务示例视频均已替换为本地生成的动态测试图案，并使用静音 AAC 音轨，不再包含录制的应用画面。可运行 `bash tools/generate-demo-videos.sh` 重新生成；素材替换后的设备播放回归尚未执行，上述设备结果属于替换前的验证记录。

最终一行全屏接入测试发现并修复了直接搬移 RecyclerView 条目根视图导致的布局参数冲突：默认 VideoViewHolder 现在提供稳定容器，协调器明确拒绝搬移适配器拥有的根条目。修复后的 API 35 完整 UI 设备复验 11 项全部通过（4 项控件/展示、7 项原有绑定回归），关闭后全命令终态契约单项复验也通过。

API 35 运行时临时关闭了系统动画以减少界面等待，验证结束后恢复了原始设置。测试 APK 显式使用目标 SDK 35，避免旧目标版本的系统提示干扰。最终构建再次通过，发布与打包校验包含新增公开 API，并排除调试宿主。

结论：请求的控制能力已实现，新增控制器及 UI 行为验证通过；整体播放器回归未全部通过，仍保留 API 35 两项现有首帧/相邻预热失败待定位。本报告不将它们归因于模拟器或宣称播放器整体已验收。

## 边界

方向遵循宿主 Activity 的配置；页面重建结束当前全屏窗口，宿主可按自己的页面状态重新进入。协调器不修改 Manifest 或强制锁方向，不创建系统悬浮窗。原有 API 35 模拟器花屏记录仍在此前报告中，本次未将其判定为已解决，也未宣称多设备画面、性能或视觉验收通过。

构建与设备证据见 `docs/verification/controls-*.log`，接入步骤见 [播放控制文档](playback-controls.md)。
